AudioFlow's first Windows x64 release. Assign an audio output to each monitor and let supported applications follow their windows.

## Included

- Native display, playback-device, window, and audio-session discovery.
- Automatic monitor routing with switching delay and overlap protection.
- Fixed-device, follow-monitor, Windows-default, and ignore rules.
- Manual Windows output preservation and managed-route restoration.
- System tray operation, Windows autostart, onboarding, and local configuration backup.
- Dark, light, and system themes, activity history, and speaker tests.
- Signed GitHub update checks with real download progress and installation confirmation.

## Install

Download `AudioFlow_0.1.0_x64-setup.exe` below and complete setup. Installation is per-user. Windows 11 is the primary target; Windows 10 compatibility has not been fully validated.

The installer has a Tauri updater signature. It does not have a Windows Authenticode certificate, so Windows may show a SmartScreen warning.

## Validation and limits

The local suite passed 17 automated tests. Two isolated Windows MediaPlayer processes were observed on separate physical outputs, including movement between displays and back. The Windows global default remained unchanged. See [the validation record](https://github.com/hazavi/AudioFlow/blob/v0.1.0/VALIDATION.md) for the full scope.

Browser tabs sharing an audio process share one output. Some applications require stream or playback recreation after a preference change. Internal Windows audio-policy interfaces can vary between Windows versions. Fresh-account installation and an installed older-to-newer upgrade remain unverified.

If you used the initial local preview, exit it through the tray before installing this release. That preview predates the configured update endpoint and needs this installer once.
